## Commands

```bash
npm run dev      # dev server on http://localhost:3000
npm run build    # production build
npm start        # serve the production build
npm run lint     # eslint (flat config via FlatCompat -> next/core-web-vitals + next/typescript)
npx tsc --noEmit # typecheck; there is no separate script for it
```

No test framework is installed — there are no tests to run.

## Architecture

Next.js 15.5.x (App Router), React 19, TypeScript (strict), Tailwind CSS v4. The project is
still the `create-next-app` scaffold: `src/app/` holds `layout.tsx` (root layout, Geist
fonts wired to CSS variables) and `page.tsx`. Import from `src/` via the `@/*` alias.

Tailwind v4 is configured entirely in `src/app/globals.css` — `@import "tailwindcss"`
plus an `@theme inline` block that maps the `--background`/`--foreground` custom
properties and the Geist font variables into Tailwind's token namespace. There is no
`tailwind.config.*`; add design tokens in that CSS block. PostCSS uses only
`@tailwindcss/postcss`.

## Working with this Next.js version

`next` and `eslint-config-next` are deliberately held on 15.5.x (`^15.5.25`, downgraded
from the 16.x scaffold). Do not bump to 16 without being asked. Consequences to keep in
mind:

- Next 16-only generated route types (`LayoutProps<"/">`, `PageProps<...>`) do not exist
  here — type route props explicitly.
- `eslint-config-next` 15 has no flat-config subpath exports, hence the `FlatCompat`
  bridge in `eslint.config.mjs` (needs the `@eslint/eslintrc` devDependency).
- `AGENTS.md` was generated by Next 16's `next dev`; 15 does not maintain it, so the
  `node_modules/next/dist/docs/` guidance it references may not match the installed
  version.
- `next build` rewrites `tsconfig.json` in place — it reformats the JSON and forces
  `"jsx": "preserve"` (the 16.x scaffold had `react-jsx`). Expect that file to show up
  dirty in `git status` after a build; it is Next doing it, not a stray edit. The
  `.next/dev/types/**/*.ts` entry in `include` is a harmless Next 16 leftover.
- `npm audit` still reports build-time advisories against `postcss` (bundled inside
  `next`) and `sharp`. The postcss one is only resolvable by moving to Next 16, so it
  is knowingly accepted while the project stays on 15.x.
